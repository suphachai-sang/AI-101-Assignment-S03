# รัฐธรรมนูญของโปรเจกต์ AI-101-Assignment-S03

## หลักการหลัก

### I. ความตรงกับต้นฉบับ
วันที่ ชื่อเหตุการณ์ และรายละเอียดทั้งหมดในอาร์ติแฟกต์ที่สร้างขึ้น ต้องสามารถ
สืบย้อนกลับไปยังเอกสารต้นฉบับที่ให้มาได้ ความไม่แน่นอนของ OCR หรือการสกัดข้อมูล
ที่ไม่สมบูรณ์ต้องถูกรายงานเพื่อตรวจทาน ระบบต้องไม่สร้างเนื้อหาที่ไม่แน่นอนขึ้นมาเอง
หรือแสดงเนื้อหาดังกล่าวราวกับว่ายืนยันแล้ว การปรับรูปแบบใดๆ ต้องคงความหมายของ
ต้นฉบับไว้

### II. ความอ่านง่ายของภาษาไทยและความสมบูรณ์ของภาพ
อินโฟกราฟิกที่สร้างขึ้นต้องแสดงข้อความภาษาไทยให้อ่านได้ชัดเจนและคงลำดับเวลาไว้
ข้อความและองค์ประกอบ timeline ต้องอยู่ภายในผืนภาพโดยไม่ถูกตัดหรือทับกันโดยไม่ได้
ตั้งใจ ความคล้ายกับภาพอ้างอิงต้องไม่สำคัญกว่าความถูกต้องของข้อมูลต้นฉบับหรือความ
อ่านง่ายของเนื้อหา

### III. การประมวลผลที่แยกส่วนและมุ่งเป้าหมาย
การนำเข้าเอกสาร การสกัดข้อความ การตรวจสอบเหตุการณ์ และการเรนเดอร์อินโฟกราฟิก
ต้องมีหน้าที่ที่ชัดเจน เพื่อให้แต่ละขั้นตอนตรวจสอบและทดสอบได้ การพัฒนาเวอร์ชันแรก
ต้องมุ่งที่รูปแบบเอกสารกำหนดการที่ให้มา ต้องไม่เพิ่มคุณลักษณะ PDF ทั่วไป แอปที่
มีสถานะฝั่งเซิร์ฟเวอร์ หรือคุณลักษณะการแก้ไข เว้นแต่ข้อกำหนดในภายหลังจะระบุไว้

### IV. ผลลัพธ์ที่ตรวจสอบได้
การพัฒนาต้องมีการทดสอบสำหรับการจัดการวันที่/เหตุการณ์ ข้อมูลที่สกัดได้ไม่ถูกต้อง
หรือไม่แน่นอน และขนาดภาพผลลัพธ์ ต้องมีการตรวจสอบแบบ end-to-end อย่างน้อยหนึ่ง
รายการที่ใช้ input ตัวอย่างที่ให้มาหรือ fixture ที่เป็นตัวแทน ผลลัพธ์ภาพต้องถูก
ตรวจสอบเทียบกับเกณฑ์การยอมรับ ไม่ใช่ตัดสินเพียงว่าสร้างไฟล์ผลลัพธ์ได้หรือไม่

### V. ข้อผิดพลาดที่ชัดเจนและการจัดการไฟล์อย่างปลอดภัย
ความล้มเหลวในการอ่าน PDF สกัดข้อความที่ใช้ได้ ตรวจสอบข้อมูลเหตุการณ์ หรือเรนเดอร์
ภาพ ต้องสร้างข้อผิดพลาดที่นำไปแก้ไขได้ แทนผลลัพธ์สำรองที่ดูเหมือนสำเร็จ เอกสาร
input ต้องคงเดิม ตำแหน่ง output และพฤติกรรมการเขียนทับต้องชัดเจน และต้องไม่เขียน
ทับไฟล์ input

## ข้อจำกัดของโปรเจกต์

- กรณีใช้งานเริ่มต้นคือ PDF กำหนดการภาษาไทยแบบสแกนที่คล้ายกับ `HW03-Input.pdf`
  โดยใช้ `HW03-Output.jpg` เป็นภาพอ้างอิงด้านรูปลักษณ์
- ผลลัพธ์อ้างอิงคือไฟล์ HTML ที่เรนเดอร์อินโฟกราฟิกอัตราส่วน 16:9 บน canvas
  ขนาด 1200 x 675 พิกเซล ข้อกำหนดคุณลักษณะอาจปรับขนาดนี้ได้ แต่การพัฒนาต้องไม่
  เปลี่ยนโดยไม่แจ้ง
- เทคโนโลยี OCR การรองรับภาษาไทย และความพร้อมของฟอนต์ต้องถูกตรวจสอบระหว่างการ
  วางแผน ผลลัพธ์ OCR ต้องถือว่าอาจผิดพลาดได้
- การรองรับ PDF ทุกรูปแบบ การแก้ไขแบบโต้ตอบ และแบ็กเอนด์เว็บแอปพลิเคชันอยู่นอก
  ขอบเขต เว้นแต่จะเพิ่มไว้ในข้อกำหนดคุณลักษณะอย่างชัดเจน

## กระบวนการพัฒนา

- ข้อกำหนดคุณลักษณะต้องกำหนดการตรวจสอบที่วัดได้สำหรับความตรงกับต้นฉบับ ความ
  อ่านง่ายของภาษาไทย ขนาดภาพ และกรณีความล้มเหลวที่เกี่ยวข้อง
- แผนงานต้องอธิบายว่าจะจัดเตรียม OCR ภาษาไทยและฟอนต์อย่างไร และจะตรวจสอบข้อมูล
  เหตุการณ์ที่สกัดได้ก่อนเรนเดอร์อย่างไร
- การทดสอบต้องครอบคลุมขั้นตอนการประมวลผลข้อมูลและอาร์ติแฟกต์สุดท้าย การรันจบ
  โดยไม่ error เพียงอย่างเดียวไม่เพียงพอที่จะพิสูจน์ว่าผลลัพธ์ถูกต้อง
- ก่อนเสร็จสิ้น ต้องตรวจสอบภาพที่สร้างขึ้นและรายงานความไม่แน่นอนของ OCR หรือ
  ข้อจำกัดที่ยังคงอยู่

## ธรรมาภิบาล

รัฐธรรมนูญฉบับนี้กำกับข้อกำหนด แผนงาน การพัฒนา และการตรวจสอบของโปรเจกต์นี้
การแก้ไขที่เสนอต้องอัปเดตเวอร์ชันและวันที่แก้ไขล่าสุดของเอกสารนี้ตาม semantic
versioning: PATCH สำหรับการชี้แจง MINOR สำหรับการเพิ่มหลักการหรือข้อจำกัด และ
MAJOR สำหรับการเปลี่ยนแปลงหรือลบที่ไม่เข้ากันได้เดิม แผนงานคุณลักษณะต้องตรวจสอบ
ความสอดคล้องก่อนพัฒนาและอีกครั้งเมื่อการออกแบบเสร็จสมบูรณ์ การเบี่ยงเบนใดๆ ต้อง
บันทึกเหตุผลไว้ในแผนงานคุณลักษณะและตรวจสอบเทียบกับเกณฑ์การยอมรับของคุณลักษณะนั้น
