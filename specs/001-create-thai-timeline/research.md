# Research: สร้างอินโฟกราฟิก Timeline ภาษาไทย

**Date**: 2026-10-15 | **Branch**: `001-create-thai-timeline`

งานวิจัยนี้ตัดสินใจทางเทคนิคทั้งหมดที่ต้องรู้ก่อนออกแบบ โดยทดสอบกับสภาพแวดล้อม
จริงของเครื่อง (macOS, Python 3.13.13) และไฟล์ตัวอย่าง `HW03-Input.pdf`

## R1: แนวทางการสกัดข้อมูลจาก PDF สแกน

**Decision**: ใช้ Tesseract OCR ภาษาไทย (`script/Thai`) ผ่าน `pytesseract`
แปลงหน้า PDF เป็นภาพด้วย PyMuPDF ที่ 200 DPI

**Rationale**:
- `pdftotext` คืนค่าว่าง — ยืนยันว่า input เป็นภาพสแกนล้วน ต้อง OCR เท่านั้น
- ทดสอบจริงบนเครื่อง: Tesseract ติดตั้งพร้อม `script/Thai` ได้ค่า confidence
  เฉลี่ย 90.9–92.7 ต่อหน้า (เกณฑ์ยอมรับ ≥ 85)
- `pytesseract.image_to_data` ให้ค่า confidence รายคำ ใช้ตรวจคำที่น่าสงสัยได้
  ตรงตาม FR-009 (แจ้งข้อมูลที่ต้องตรวจทานแทนการเดา)
- Python 3.13.13 มี PyMuPDF 1.26.7 และ pytesseract 0.3.13 ติดตั้งแล้ว

**Alternatives considered**:
- ดึง text layer ด้วย pypdf/pdfminer — ตัดออก เพราะไฟล์ไม่มี text layer
- OCR ผ่าน cloud API — ตัดออก เพราะเพิ่ม dependency ภายนอก ไม่จำเป็น และ
  ขัดกับสมมติฐานที่ต้องการเครื่องมือที่ทำงานในเครื่องได้

## R2: การเรนเดอร์ผลลัพธ์เป็น HTML canvas

**Decision**: สร้าง HTML ไฟล์เดียวแบบ self-contained — ใส่ข้อมูลเหตุการณ์เป็น
JSON ฝังใน `<script>` และวาดด้วย Canvas 2D API ล้วน ไม่ใช้ library ภายนอก

**Rationale**:
- ตรง FR-003: ไฟล์เดียว ใช้งานได้เอง ไม่ต้องติดตั้งทรัพยากรภายนอก เปิดด้วย
  เบราว์เซอร์สมัยใหม่ได้ทันที
- Canvas 2D API รองรับการวาดเส้น วงกลม ข้อความ และตัวอักษรไทยผ่านฟอนต์ระบบ
- การทดสอบขนาด canvas 1200×675 และตำแหน่งองค์ประกอบทำได้ใน Node/headless
  หรือตรวจผ่านเบราว์เซอร์อัตโนมัติ

**Alternatives considered**:
- สร้างภาพ PNG ด้วย Pillow ฝั่ง Python — ตัดออก เพราะผู้ใช้ระบุชัดว่าต้องการ
  HTML canvas (Pillow ยังคงใช้ตรวจขนาดผลลัพธ์ทดสอบอื่นได้)
- ใช้ chart library (เช่น Chart.js, vis-timeline) — ตัดออก เพราะฝัง CDN จะ
  ขัด FR-003 (self-contained) และฝังทั้งไลบรารีจะทำให้ไฟล์ใหญ่โดยไม่จำเป็น

## R3: ฟอนต์ภาษาไทยสำหรับ canvas

**Decision**: ฝัง Sarabun Regular/Bold (Open Font License) เป็น data URI ใน HTML
และใช้ผ่าน `ctx.font` โดยมีฟอนต์ระบบเป็น fallback

**Rationale**:
- ภาพอ้างอิงมีลักษณะใกล้ตระกูล TH Sarabun New; ฟอนต์ Sarabun จาก
  [Google Fonts](https://github.com/google/fonts/tree/main/ofl/sarabun)
  เป็นฟอนต์ในตระกูลเดียวกัน แต่ไม่สามารถยืนยันชื่อฟอนต์ต้นฉบับจากไฟล์ JPG ได้
- การฝังฟอนต์ใน HTML ทำให้ภาพที่เรนเดอร์บนเครื่องอื่นสม่ำเสมอและยังเป็นไฟล์เดียว
- เก็บข้อความ OCR/ข้อมูลต้นฉบับตามเดิม แล้วแปลงเลขไทยเป็นอารบิกเฉพาะตอนวาด

**Alternatives considered**:
- ใช้ Thonburi UI/Tahoma จากระบบ — ภาพต่างกันตามเครื่องและรูปตัวอักษร
  ห่างจากภาพอ้างอิงมากกว่า Sarabun

## R4: การตีความวันที่ พ.ศ. แบบย่อ

**Decision**: แปลงตัวเลขไทยเป็นอารบิกก่อน แล้วตีความปี 2 หลักด้วยบริบทปีงบประมาณ
ในหัวเรื่อง (พ.ศ. ๒๕๗๐): เดือน ต.ค.–ธ.ค. → ปีงบประมาณ−2 (๒๕๖๘), เดือน ม.ค.–ก.ย.
→ ปีงบประมาณ−1 (๒๕๖๙) สำหรับรอบปีงบประมาณนี้

**Rationale**:
- ตรงสมมติฐานใน spec: "๖๘" คือ ๒๕๖๘ และ "๖๙" คือ ๒๕๖๙
- กฎเดียวกันใช้ซ้ำได้กับเอกสารรูปแบบเดียวกันปีอื่น โดยอ้างอิงปีในหัวเรื่องเสมอ
- หากตีความไม่ได้ ต้องแจ้งตาม FR-009 ไม่เดา

**Alternatives considered**:
- เก็บวันที่เป็นข้อความดิบไม่แปลง — ตัดออก เพราะการเรียงเวลา (FR-004) ต้องการ
  วันที่ที่เปรียบเทียบได้

## R5: เกณฑ์ความมั่นใจของ OCR

**Decision**: ใช้ค่า confidence เฉลี่ยทั้งเอกสาร ≥ 85 และคำที่ confidence < 60
ถูกทำเครื่องหมาย "ต้องตรวจทาน" ในรายงาน ไม่ใส่ในผลลัพธ์โดยเงียบ

**Rationale**: ตรงหลัก constitution ข้อ I (Source Fidelity) และ FR-009 — ค่าจาก
การทดสอบจริง (≈91–93) อยู่เหนือเกณฑ์เอกสาร แต่ผลต้นแบบสกัดได้เพียง 4
เหตุการณ์ จึงต้องตรวจความครบถ้วนของ 3 กลุ่มและเทียบกับรายการเหตุการณ์ที่
ตรวจจาก PDF ด้วยตา ไม่ถือว่าค่าเฉลี่ย OCR ผ่านแล้วข้อมูลถูกต้องอัตโนมัติ

## R6: การจัดวาง timeline ให้ไม่ทับกัน

**Decision**: วางเหตุการณ์สลับด้านบน/ล่างของแกนกลางแนวนอน ข้อความห่อบรรทัดด้วย
การวัดความกว้างผ่าน `ctx.measureText` กำหนดจำนวนเหตุการณ์สูงสุดที่แสดง (≈10–12)
และเก็บรายการทั้งหมดไว้ใน JSON ฝังไฟล์เผื่อขยายในอนาคต

**Rationale**: ตรง FR-005/FR-007 — วัดขนาดข้อความจริงก่อนวาดทุกครั้ง และ
ห่อข้อความยาวของภาษาไทยตามคำที่ OCR แยกได้ โดยไม่เปลี่ยนสาระ
