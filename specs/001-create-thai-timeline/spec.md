# ข้อกำหนดคุณลักษณะ (Feature Specification): สร้างอินโฟกราฟิก Timeline ภาษาไทย

**Feature Branch**: `001-create-thai-timeline`  
**สร้างเมื่อ**: 2026-10-15  
**สถานะ**: ร่าง (Draft)  
**Input**: คำอธิบายจากผู้ใช้: "สร้างสคริปต์ที่รับ PDF กำหนดการภาษาไทยแบบสแกน แล้วสร้างอินโฟกราฟิก timeline เป็นไฟล์ HTML ที่เรนเดอร์ด้วย canvas ให้คล้ายกับ HW03-Output.jpg"

## สถานการณ์ผู้ใช้และการทดสอบ *(บังคับ)*

### User Story 1 - สร้างอินโฟกราฟิกกำหนดการ (ลำดับความสำคัญ: P1)

ในฐานะผู้ใช้ที่มี PDF กำหนดการภาษาไทยแบบสแกน ฉันต้องการแปลงเหตุการณ์สำคัญในเอกสาร
ให้เป็นอินโฟกราฟิก timeline เพื่อให้เข้าใจและนำเสนอกำหนดการได้อย่างรวดเร็ว

**เหตุผลของลำดับความสำคัญนี้**: การสร้างอินโฟกราฟิกจากเอกสารที่ให้มาคือ
ผลลัพธ์หลักของคุณลักษณะนี้

**การทดสอบแบบอิสระ**: ใช้ `HW03-Input.pdf` เป็น input แล้วตรวจว่าระบบสร้าง
ไฟล์ HTML ที่เรนเดอร์ timeline ด้วย canvas โดยมีหัวเรื่อง วันที่ ผู้รับผิดชอบ
และรายละเอียดเหตุการณ์เรียงตามลำดับเวลาได้

**สถานการณ์ยอมรับ (Acceptance Scenarios)**:

1. **เมื่อมี** PDF กำหนดการ 3 หน้าที่ให้มา **และผู้ใช้**สั่งสร้างอินโฟกราฟิก
   **ระบบต้อง**สร้างไฟล์ HTML ที่เรนเดอร์ canvas ขนาด 1200 x 675 พิกเซล ประกอบด้วย
   timeline แนวนอน ข้อความภาษาไทย และเหตุการณ์สำคัญจากเอกสารต้นฉบับ
2. **เมื่อมี**กำหนดการที่ถูกต้องซึ่งมีหลายเหตุการณ์ **และระบบ**สร้างไฟล์ HTML
   แล้ว **เหตุการณ์ต้อง**เรียงตามลำดับเวลา และรายละเอียดต้องคงความหมายตรงต้นฉบับ
3. **เมื่อเปิด**ไฟล์ HTML ที่สร้างแล้ว**ในเว็บเบราว์เซอร์ที่ขนาดตามจริง** หัวเรื่อง
   ป้ายวันที่ และรายละเอียด**ต้อง**อ่านได้ชัดเจน และไม่มีข้อความหรือองค์ประกอบ
   timeline ใดถูกตัดหรือทับกันโดยไม่ได้ตั้งใจ
4. **เมื่อ**ระบบสร้างผลลัพธ์จาก `HW03-Input.pdf` **ระบบต้อง**สกัดและแสดง
   หัวเรื่องปฏิทินงบประมาณและกลุ่มกิจกรรมหลัก 3 กลุ่ม ได้แก่ "การทบทวนและวางแผน
   งบประมาณ" "การจัดทำงบประมาณ" และ "การอนุมัติงบประมาณ" รวมถึงหมายเลขลำดับ
   เหตุการณ์ วันเดือนปี ผู้รับผิดชอบ และรายละเอียดกิจกรรมของเหตุการณ์ที่เลือกมา
   แสดงให้ตรงกับต้นฉบับ

### User Story 2 - ระบุข้อมูลที่ต้องตรวจทาน (ลำดับความสำคัญ: P2)

ในฐานะผู้ใช้ ฉันต้องการให้ระบบแจ้งเมื่ออ่านเอกสารต้นฉบับไม่ได้อย่างน่าเชื่อถือ
เพื่อที่ฉันจะได้ไม่เข้าใจผิดว่าวันที่หรือรายละเอียดที่ไม่ถูกต้องเป็นข้อมูลที่ยืนยันแล้ว

**เหตุผลของลำดับความสำคัญนี้**: กำหนดการที่ทำให้เข้าใจผิดแย่กว่าการหยุดและอธิบาย
ว่าต้องแก้ไขอะไร

**การทดสอบแบบอิสระ**: ใช้ PDF ที่อ่านไม่ได้หรือไม่รองรับ แล้วตรวจว่าระบบแจ้งปัญหา
และไม่แสดงไฟล์ HTML สุดท้ายราวกับว่าเป็นผลลัพธ์ที่ยืนยันแล้ว

**สถานการณ์ยอมรับ (Acceptance Scenarios)**:

1. **เมื่อ**วันที่หรือรายละเอียดเหตุการณ์ที่จำเป็นอ่านไม่ได้อย่างน่าเชื่อถือ
   **และมีการ**สั่งสร้างไฟล์ HTML **ระบบต้อง**ระบุข้อมูลที่ต้องตรวจทาน และต้องไม่
   สร้างค่าขึ้นมาเองโดยเงียบ
2. **เมื่อมี**ไฟล์ที่ไม่ใช่ PDF กำหนดการที่อ่านได้ **และมีการ**สั่งสร้างไฟล์ HTML
   **ระบบต้อง**แจ้งว่าไม่สามารถสร้างอินโฟกราฟิกที่ขอได้ พร้อมอธิบายสิ่งที่ควรทำต่อไป

### กรณีขอบ (Edge Cases)

- PDF ไม่มีอยู่ เสียหาย ติดรหัสผ่าน หรือไม่มีหน้าที่อ่านได้
- หน้าเอกสารไม่มีรายการกำหนดการที่รู้จัก หรืออ่านวันที่/รายละเอียดได้เพียงบางส่วน
- สองเหตุการณ์มีวันที่เดียวกัน หรือช่วงวันที่ข้ามช่วงปฏิทิน หรือข้ามปีงบประมาณ
- ข้อความภาษาไทยยาวเกินไปที่จะวางข้างเหตุการณ์อื่นที่ขนาด canvas เป้าหมาย
- ตำแหน่งไฟล์ output ที่ขอมีอยู่แล้ว หรือชี้ไปที่ไฟล์ PDF input
- ผู้ใช้เปิดไฟล์ HTML ในเบราว์เซอร์ที่ไม่รองรับ canvas
- เอกสารมีหมายเหตุท้ายตาราง (เช่น เงื่อนไขตามรัฐธรรมนูญ) ที่ไม่ใช่เหตุการณ์ของ
  timeline — ระบบต้องไม่นำหมายเหตุเหล่านี้มาสร้างเป็นเหตุการณ์
- วันที่ในเอกสารเป็นปี พ.ศ. แบบย่อ (เช่น "ต.ค. ๖๘" หมายถึงตุลาคม ๒๕๖๘) —
  ระบบต้องตีความปีให้ถูกต้องตามบริบทของปีงบประมาณที่ระบุในหัวเรื่อง
- ตารางในเอกสารมีรายการย่อยหลายรายการภายใต้ช่วงวันที่เดียวกัน หรือเหตุการณ์ที่
  ช่วงวันที่ซ้อนทับกัน

## ข้อกำหนด *(บังคับ)*

### ข้อกำหนดเชิงหน้าที่ (Functional Requirements)

- **FR-001**: ระบบต้องรับ `HW03-Input.pdf` ที่ตรวจทานข้อมูลกับภาพสแกนแล้ว
  หากเป็น PDF อื่น ต้องแจ้งให้ตรวจทานตาม FR-009 ก่อนแสดงผลลัพธ์ที่ยืนยันแล้ว
- **FR-002**: ระบบต้องระบุหัวเรื่องของเอกสาร กลุ่มกิจกรรมหลัก วันที่หรือช่วง
  วันที่ของเหตุการณ์ หน่วยงานผู้รับผิดชอบ และรายละเอียดย่อที่จำเป็นสำหรับ
  timeline โดยสำหรับ `HW03-Input.pdf` ต้องครอบคลุมกลุ่มกิจกรรมหลัก 3 กลุ่ม ได้แก่
  "การทบทวนและวางแผนงบประมาณ" "การจัดทำงบประมาณ" และ "การอนุมัติงบประมาณ"
- **FR-003**: ระบบต้องสร้างไฟล์ HTML ที่เรนเดอร์อินโฟกราฟิก timeline แนวนอน
  ภาษาไทยบน canvas ขนาด 1200 x 675 พิกเซลพอดี โดยไฟล์ต้องใช้งานได้เองโดยไม่ต้อง
  ติดตั้งทรัพยากรเพิ่มเติมจากภายนอก
- **FR-004**: ระบบต้องวางเหตุการณ์ตามลำดับเวลา โดยคงความหมายของวันที่และ
  รายละเอียดให้ตรงกับต้นฉบับ
- **FR-005**: ระบบต้องเก็บข้อความและองค์ประกอบภาพทั้งหมดให้อยู่ในภาพ และหลีกเลี่ยง
  การทับกันโดยไม่ได้ตั้งใจ
- **FR-006**: ระบบต้องรองรับการอ่านและตีความปีพุทธศักราช ทั้งรูปแบบเต็มและรูปแบบ
  ย่อ โดยอ้างอิงกับปีงบประมาณที่ระบุในหัวเรื่องเอกสาร (เช่น พ.ศ. ๒๕๗๐)
- **FR-007**: ระบบต้องสละรายละเอียดของเหตุการณ์ให้สั้นลงเพื่อให้อ่านได้บนพื้นที่
  จำกัดได้ โดยต้องไม่เปลี่ยนข้อเท็จจริงของวันที่ ผู้รับผิดชอบ หรือสาระสำคัญของ
  กิจกรรม
- **FR-008**: ระบบต้องไม่สร้างเหตุการณ์จากส่วนหมายเหตุท้ายตารางที่ไม่ใช่กิจกรรม
  ของกำหนดการ (เช่น เงื่อนไขตามรัฐธรรมนูญ)
- **FR-009**: เมื่อข้อมูลที่จำเป็นอ่านไม่ได้อย่างน่าเชื่อถือ ระบบต้องแจ้งสิ่งที่ต้อง
  ตรวจทาน และต้องไม่แสดงไฟล์ HTML สุดท้ายราวกับว่าเป็นผลลัพธ์ที่ยืนยันแล้ว
- **FR-010**: ระบบต้องแจ้งข้อผิดพลาดที่นำไปแก้ไขได้ เมื่อไฟล์ input ไม่มีอยู่
  อ่านไม่ได้ หรือไม่รองรับ
- **FR-011**: ระบบต้องไม่แก้ไขไฟล์ PDF input และต้องไม่เขียนไฟล์ output ทับไฟล์
  ดังกล่าว
- **FR-012**: ระบบต้องแจ้งข้อผิดพลาดแทนการเขียนทับไฟล์ output ที่มีอยู่แล้ว
  หากผู้ใช้ไม่ได้อนุมัติอย่างชัดเจน
- **FR-013**: ระบบต้องใช้ `HW03-Output.jpg` เป็นภาพอ้างอิงด้านสัดส่วน สี
  รูปแบบแกนเวลา และการจัดวางเท่านั้น ห้ามนำปี วันที่ หรือรายละเอียดกิจกรรม
  จากภาพอ้างอิงมาแทนข้อมูลใน `HW03-Input.pdf`
- **FR-014**: หมายเลขเหตุการณ์คี่ทุกหมายเลขที่แสดงต้องอยู่เหนือแกนเวลา
  และหมายเลขคู่ทุกหมายเลขที่แสดงต้องอยู่ใต้แกนเวลา
- **FR-015**: ตัวเลขทุกตำแหน่งที่มองเห็นในภาพผลลัพธ์ต้องเป็นตัวเลขอารบิก
  รวมถึงปีในหัวเรื่อง วันที่ และแถบเดือน โดยข้อมูลต้นฉบับที่ฝังไว้ยังคงรูปเดิม

### เอนทิตีหลัก (Key Entities)

- **เอกสารกำหนดการ (Schedule document)**: PDF ที่ให้มา ซึ่งมีหัวเรื่อง ตาราง
  กำหนดการหลายหน้า และหมายเหตุท้ายตาราง
- **กลุ่มกิจกรรม (Activity group)**: ส่วนหัวข้อหลักของตารางที่รวมเหตุการณ์
  ที่เกี่ยวข้องกัน (สำหรับ `HW03-Input.pdf` ได้แก่ การทบทวนและวางแผนงบประมาณ,
  การจัดทำงบประมาณ, การอนุมัติงบประมาณ)
- **เหตุการณ์ (Milestone)**: กิจกรรมที่มีวันที่ ประกอบด้วยหมายเลขลำดับ วันที่หรือ
  ช่วงวันที่ (ปีพุทธศักราช) หน่วยงานผู้รับผิดชอบ และรายละเอียดย่อที่ตรงกับต้นฉบับ
- **อินโฟกราฟิก timeline (Timeline infographic)**: ไฟล์ HTML ที่เรนเดอร์ canvas
  ขนาด 1200 x 675 พิกเซล แสดงเหตุการณ์ที่เลือกเรียงตามลำดับเวลา พร้อมหัวเรื่อง
  และคำอธิบายแต่ละเหตุการณ์

## เกณฑ์ความสำเร็จ *(บังคับ)*

### ผลลัพธ์ที่วัดได้ (Measurable Outcomes)

- **SC-001**: เมื่อใช้ input ที่ให้มา ระบบสร้างไฟล์ HTML ที่เรนเดอร์ canvas
  ขนาด 1200 x 675 พิกเซลพอดี
- **SC-002**: วันที่และรายละเอียดเหตุการณ์ทุกรายการที่แสดงในผลลัพธ์สุดท้ายสามารถ
  เชื่อมโยงกลับไปยังข้อมูลในเอกสารต้นฉบับได้ และไม่มีรายละเอียดที่ต้นฉบับไม่มี
  ถูกเพิ่มเข้ามา
- **SC-003**: เหตุการณ์ทั้งหมดที่เลือกมาแสดงในอินโฟกราฟิกเรียงตามลำดับเวลา
  รวมถึงช่วงวันที่และวันที่ที่ซ้ำกัน
- **SC-004**: เมื่อเปิดไฟล์ HTML ในเว็บเบราว์เซอร์ที่ขนาดตามจริง ข้อความภาษาไทย
  ทั้งหมดที่แสดงสามารถอ่านได้ โดยไม่ถูกตัดหรือทับกันโดยไม่ได้ตั้งใจ
- **SC-005**: เมื่อข้อมูลต้นฉบับที่จำเป็นไม่แน่นอนหรือประมวลผลไฟล์ไม่ได้ ระบบแจ้ง
  ปัญหาและไม่สร้างผลลัพธ์สุดท้ายที่ทำให้เข้าใจผิดโดยเงียบ
- **SC-006**: เมื่อประมวลผล `HW03-Input.pdf` ระบบสกัดเหตุการณ์ที่มีวันที่ชัดเจน
  ครอบคลุมกลุ่มกิจกรรมหลักทั้ง 3 กลุ่ม ครบถ้วน และไม่สร้างเหตุการณ์จากหมายเหตุ
  ท้ายตาราง
- **SC-007**: ผลลัพธ์ของไฟล์ตัวอย่างแสดงปีงบประมาณ พ.ศ. ๒๕๗๐ ตาม PDF
  และไม่ใช้ปีงบประมาณ พ.ศ. ๒๕๖๙ ของภาพอ้างอิงเป็นข้อมูลต้นฉบับ
- **SC-008**: ภาพผลลัพธ์ไม่มีหมายเลขคี่อยู่ใต้แกนเวลาหรือหมายเลขคู่อยู่เหนือแกนเวลา
- **SC-009**: ภาพผลลัพธ์ใช้ตัวเลขอารบิกทุกตำแหน่ง และฟอนต์ไทยมีหน้าตา
  สม่ำเสมอเมื่อเปิด HTML โดยไม่ต้องดาวน์โหลดฟอนต์เพิ่ม

## สมมติฐาน (Assumptions)

- เวอร์ชันแรกรองรับเอกสารกำหนดการภาษาไทยที่ให้มา และเอกสารที่มีรูปแบบใกล้เคียง
  เท่านั้น PDF ประเภทอื่นที่ไม่จำกัดอยู่นอกขอบเขต
- `HW03-Output.jpg` แสดงปีงบประมาณ พ.ศ. ๒๕๖๙ ส่วน `HW03-Input.pdf`
  แสดงปีงบประมาณ พ.ศ. ๒๕๗๐ จึงใช้ JPG เป็นภาพอ้างอิงด้านองค์ประกอบ
  และรูปลักษณ์เท่านั้น
- อินโฟกราฟิกสรุปเหตุการณ์สำคัญ ไม่ใช่การทำซ้ำทุกย่อหน้าของเอกสารต้นฉบับ
  การเลือกเหตุการณ์ให้ครอบคลุมทุกกลุ่มกิจกรรมหลักสำคัญกว่าจำนวนเหตุการณ์ทั้งหมด
  ที่แสดง
- ปีในตารางเป็นรูปแบบปีพุทธศักราชย่อ (เช่น "๖๘" ในรอบงบประมาณ
  พ.ศ. ๒๕๗๐ คือ พ.ศ. ๒๕๖๘ และ "๖๙" คือ พ.ศ. ๒๕๖๙) ระบบจะแสดงปีในผลลัพธ์
  อย่างน้อยในรูปแบบเดียวกับต้นฉบับ
- ผลลัพธ์เริ่มต้นเป็นไฟล์ HTML ไฟล์เดียวที่เรนเดอร์ canvas ขนาด 1200 x 675 พิกเซล
  ผู้ใช้ระบุตำแหน่ง output อื่นได้ และระบบจะไม่เขียนทับไฟล์ที่มีอยู่แล้วโดยไม่ได้
  รับอนุมัติชัดเจน

  ข้อมูลที่ไม่แน่นอนจะถูกแจ้งให้ตรวจทานแทน
